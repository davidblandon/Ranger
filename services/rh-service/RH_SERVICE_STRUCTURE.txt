RH SERVICE STRUCTURE GUIDE

This document explains, in English, what each folder and file in the current rh-service microservice is for, and lists their actual locations.

1. Top-level files (service root)

- `pom.xml` — Maven project file: Java version, Spring Boot parent, dependencies and build plugins.
- `Dockerfile` — Container image build instructions (copies the jar and exposes port 8082).
- `README.md` — High-level run instructions and architecture notes.
- `RH_SERVICE_STRUCTURE.txt` — This file (project structure guide).
- `.gitignore` — Git ignore rules.
- `mvnw`, `mvnw.cmd`, `.mvn/` — Maven wrapper files to build the project without a local Maven install.
- `.gitkeep` — placeholder file present in the repository.

Note: the Java sources and runtime config are under `src/main/...` (see below).

2. Application layer (src/main/java/com/example/rhservice/application)

2.1 `application/port/in/`

- `CrudUseCase.java` — Generic CRUD contract for application services (findAll, findById, save, delete).
- `EmployeeService.java` — Use-case contract for employee operations.
- `AdminService.java` — Use-case contract for admin operations.
- `PayrollService.java` — Use-case contract for payroll operations.
- `ShiftService.java` — Use-case contract for shift operations.

2.2 `application/port/out/`

- `CrudPersistencePort.java` — Generic persistence port used by the abstract service.
- `EmployeePersistencePort.java` — Persistence port for employees.
- `AdminPersistencePort.java` — Persistence port for admins.
- `PayrollPersistencePort.java` — Persistence port for payrolls.
- `ShiftPersistencePort.java` — Persistence port for shifts.

2.3 `application/service/impl/`

- `AbstractCrudService.java` — Base service implementing common CRUD behavior.
- `EmployeeServiceImpl.java` — Employee use-case implementation.
- `AdminServiceImpl.java` — Admin use-case implementation.
- `PayrollServiceImpl.java` — Payroll use-case implementation.
- `ShiftServiceImpl.java` — Shift use-case implementation.

3. Domain layer (src/main/java/com/example/rhservice/domain/model)

- `User.java` — Abstract base JPA entity for shared user fields (name, telephone, address, bank account).
- `Employee.java` — `@Entity` extending `User`; fields: monthlyHours, salary, assigned `Shift`, payroll list.
- `Admin.java` — `@Entity` extending `User`; fields: permissions.
- `Payroll.java` — `@Entity` representing payroll records linked to an employee.
- `Shift.java` — `@Entity` storing a weekly schedule (uses `TimeBlock`).
- `TimeBlock.java` — `@Embeddable` value object for start/end `LocalTime` intervals.

4. Infrastructure (src/main/java/com/example/rhservice/infrastructure/persistence)

4.1 `jpa/` — Spring Data JPA repositories

- `EmployeeJpaRepository.java`
- `AdminJpaRepository.java`
- `PayrollJpaRepository.java`
- `ShiftJpaRepository.java`

4.2 `adapter/` — Persistence adapters implementing application output ports

- `EmployeePersistenceAdapter.java`
- `AdminPersistenceAdapter.java`
- `PayrollPersistenceAdapter.java`
- `ShiftPersistenceAdapter.java`

5. Other packages under `com.example.rhservice`

- `repository/` — currently empty; leftover from prior structure (kept as placeholder).
- `service/impl/` — currently empty; legacy folder (actual implementations are in `application/service/impl`).

6. Resources and application entry

- `src/main/resources/application.yml` — Runtime configuration (server port 8082, H2 settings, JPA properties, actuator endpoints).
- `src/main/java/com/example/rhservice/RhServiceApplication.java` — Spring Boot `main()` class (application entry point).

7. Build output and temporary files

- `target/` — Maven build output (generated by building the project). This directory is ignored by Git.

8. Summary

This file now reflects the actual files and locations in the `rh-service` module: the project follows a clean/hexagonal layout with `domain`, `application` (ports + services), and `infrastructure` (JPA + adapters). Some legacy package folders remain empty as placeholders (`repository`, `service/impl`).
